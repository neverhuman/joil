# Executed-control gate for source-only baseline findings

Audit A-003 correctly notes that a future-regression text field is insufficient. The integrator adds a primary-task receipt check in `tools/v5_plan.py`: every source-only finding must have a distinct `defect_controls` entry with its frozen source binding, a tracked fixture whose bytes match its receipt artifact, an executed positive command and a nonzero red-control command, exact exit codes and raw log hashes. Positive commands must be among the completion receipt's successful commands. Missing, duplicate, stale, unrelated or zero-exit red entries fail loading/updating progress.

Seven source-only rows already map to accepted primary software receipts at cutover: D-10 (V5-02-01), D-17/D-21 (V5-01-04), D-24 (V5-01-05), D-27 (V5-05-05), D-28 (V5-00-05), and D-29 (V5-03-05). The gate retains only those exact path/hash references, not a general prior-done bypass. Their receipts retain their declared scope and limitations; this does not retroactively label the16baseline source-only rows as executed. The nine other primary tasks remain open and cannot use inventory completion as executed repair evidence. New/replacement primary receipts, including replacements for a cutover receipt, must satisfy the gate. These software receipts do not admit physical inputs or physical qualification.

This adds only the integrator-owned plan validator, its boundary tests and the execution registry. Historical receipts and the original DEFECTS inventory stay unchanged. Baseline task03's inventory-criterion clarification still awaits the independent acknowledgement requested by A-003; this enforcement is not that acknowledgement and does not itself close the audit hold.
