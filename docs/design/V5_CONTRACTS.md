# Restricted physical contracts

V5-03 implements software contracts, not physical qualification. The exact path registry includes a dedicated `crucible-architecture` workspace test package, as task 05 requires; the original path list omitted that package. Integrator alone registers it and the two implementation crates. This narrow scope correction activates no additional packet or worker.

The single semantic identity and strict JSON implementation remains `joil-evidence`. `BlobDigest` hashes exact stored bytes; `SemanticId` hashes the versioned canonical scientific value. They are different types. Signed gauge pressure is supported; concentration retains dispersed-oil mg/L basis. Density and concentration share dimensions but have distinct quantity kinds. Conversion to volume fraction requires an explicit oil density. The bounded arithmetic AST has no scripting or I/O and separates mechanical-loss power per treated flow from a pressure proxy. Coordinates and proper rigid transforms use explicit SI frames; the orthogonality tolerance is a numerical representation policy.

`SubjectBundle` contains physical artifacts, declared approximation bounds, transform, material/roughness state, numeric contract ports and frozen boundaries. It has no genome, module registry, ancestry, display label or expected score. Render/origin sidecars belong outside this evaluator wire. Unknown material and roughness remain explicit and cannot establish manufacturing qualification. Verification requires exact artifact/frozen-boundary bytes and current authenticated interface/acceptance reviews under the requirement scope. It is byte/contract closure, not an independent cavity or mesh-quality observer. Native geometry observation remains V5-09. STEP/native solver adapters remain future scoped work.

Worker execution, observation availability, gate resolution and claim eligibility are distinct. Worker JSON cannot construct `GateDecision` or `ClaimEligibility`. Only current source-bound registry resolution yields a gate Pass/Fail; numerical/infrastructure failure and unsupported/out-of-scope evidence remain distinct Unknown reasons. Missing output cannot pass. NotApplicable requires the predeclared, independently resolved rule. Eligibility checks an exact nonempty reviewed gate inventory and rechecks policy and claim freshness. ReadyForEvidenceReview is software evidence readiness, never an authorization for physical performance claims.

Observation cache keys bind the complete subject, manufacturing state, scenario, solver build/container, numerics, mesh/sampling/randomness/extractor/calibration. Uncalibrated is explicit. Decision keys additionally bind requirements/profile/preferences, so reranking cannot alter old observations. Durable closure/revocation and campaign budget enforcement are V5-05/06 dependencies.

The dedicated architecture package traverses Cargo's resolved normal, build and dev edges, including renamed dependencies. Synthetic indirect forbidden bridges must fail. Judge/evaluator roles and registry/search/origin roles are declared by metadata, with reserved package names also enforced. This compile-time graph check is not process isolation or a proof against arbitrary native code; runtime isolation is a separate dependency. Interchange schemas are strict structural contracts; Rust semantic checks and current reviews remain mandatory. Generated TypeScript describes JSON shape, not an authority to submit verdicts. All public fixtures are synthetic software examples.

Review found that the legacy registry resolves a claim under its own admitted requirements. V5-03 therefore adds only a scoped resolver method in `joil-evidence/src/claims.rs` (integrator-owned shared contract): the gate supplies its active requirements, and mismatched claim scope returns Invalid. The original resolver remains compatible. This narrow registry addition is recorded before the shared edit; no Claude path overlaps it.
