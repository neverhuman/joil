# Private immutable store

V5-05 is a software artifact store. It cannot establish physical correctness. The integrator alone serializes new crate/workspace/lock registration; this narrow registry correction adds those omitted supporting paths before edits.

The Linux implementation anchors directory/file operations to open directory descriptors, uses no-follow opens, and accepts only typed digest object names. Roots must be in an explicitly private/ignored directory. Worker payloads cannot choose paths. New same-filesystem staging directories contain exact payload/manifest bytes, both fsynced and hash-verified before atomic rename and parent fsync. Concurrent identical publication is idempotent; conflicting/corrupt destinations fail. Partial stages remain quarantined and cannot be read as objects. No source cleanup or global settings are involved.

An immutable manifest binds payload storage digest, optional canonical semantic identity, full parent object IDs, content type, typed purpose, array shape/layout/units, and inherited disclosure. Exact cache lookup requires the complete verified closure and exact evaluation identity plus its bound dependency blobs. Near-duplicate fingerprints are a separate advisory index. Current reads recheck append-only invalidations transitively; historical bytes remain readable with explicit stale status. This is evidence freshness, not a claim that rendered pixels were physically validated.

Remote storage uses immutable uploads and an explicit conditional generation pointer protocol. The exercised backend is a deterministic software test backend; no cloud provider connection or remote-worker readiness is claimed. SQLite remains local in V5-06. Backup restoration verifies hashes and full closure before selecting a root and reports/falls back from invalid latest roots. Retention traces complete accepted/checkpoint roots, including governing meshes/fields/raw reductions. Public export requires a current authenticated exact allowlist and fully public-candidate ancestry; an image of private geometry inherits private status. No export is published externally by this packet.

The implemented retention API persists pins and rereads them under the same coordinator file lock as publication before moving unreachable objects to reversible GC quarantine. Pinning is retention only; object-kind labels confer no admission. Backups preserve the included pins and append-only invalidation prefix. Exact cache indexes are rebuildable and are not a replacement for checkpoint state. Linux/procfs, local filesystem rename/fsync and advisory file-lock semantics are explicit prerequisites; process SIGKILL is tested, not a storage-device power-loss experiment. Manifest decoding has the kernel size limit; payload and closure byte/count/depth budgets bound reads. No destructive erasure or cloud provider adapter is implemented.

A review follow-up separates private backups from reviewed exports: export copies only the exact selected immutable object closure into a fresh destination, while holding source invalidation serialization. Private coordinator journals, retention roots, indexes and unrelated destination files are not export content. A synthetic unselected-reason canary reproduces the former journal leak before the fix; old receipts remain immutable.
