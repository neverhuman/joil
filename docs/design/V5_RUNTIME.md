# Transactional fixture runtime

V5-06 implements bounded software fixture execution, not a physical campaign or solver qualification. Its original write registry omitted the normal crate manifest/library, owned fixture executable, runtime design and serialized workspace registration. The integrator records those exact supporting paths before creation; V5-07 checkpoint/replay paths remain separate and inactive until accepted V5-06. No Claude-owned legacy path transfers.

Tasks, attempts, leases, events, object references, reservations, charges and experiment-family decisions persist transactionally in local SQLite. Verified store closure and exact evaluation identity precede a live-fence commit. CPU/GPU time spend is cumulative; RAM/VRAM/scratch reservations represent concurrent occupancy. Actual retries and failed/unsupported work remain charged separately from deterministic logical operations. Family policy and spent attempts cannot reset on resume or fork.

Native child processes are restricted to the deterministic synthetic fixture executable. Their process group, affinity, limits, numerical-library environment, deadline and private scratch are task-owned. Physical topology comes from sysfs and the actual allowed affinity; no modulo mapping or historical GPU authorization is accepted. Unsupported native/MPI/GPU capabilities stay explicit until separately implemented and authorized. No other project's process is signaled.

The current schema starts at a new empty versioned database; unknown versions and unversioned nonempty databases are rejected without rewriting their bytes. Online SQLite backup is verified separately from artifact-store backup. A SQLite no-follow open uses the validated directory's resolved path, since SQLite rejects the procfs descriptor symlink. Private directory handles remain open for fsync. All SQL numeric conversions are checked.

Admission compares remaining cumulative CPU/GPU time and physical block I/O with outstanding reservations; RAM/VRAM/scratch are simultaneous occupancy. Any actual overrun stays charged and halts further admissions. Child CPU hard-limit representation has a bounded rounding/headroom allowance; wall/scratch polling is not a hard realtime guarantee. The trusted single-process fixture writes an independent OS/environment audit and self-terminates at the earlier task-lease deadline or bounded lifetime even if its coordinator dies. Coordinator thread CPU through verification is included; shared coordinator memory and final bookkeeping are explicitly excluded from the per-attempt measurement scope and stay within the worker's outer lease. Cold/warm block I/O and actual time may differ; no timing equality is asserted.

Family spending uses current reviewed policy bytes and a conservative exact decimal trillionth grid. Each attempt reserves the full frozen allotment; unavailable precision is Unsupported. A fork must retain the same canonical coordinator database so ordinal/alpha/resource spend cannot reset. The full DecisionProfile adapter also validates exact allocation arithmetic and all V5-02 scope/model/sampling rules. These records are spending evidence, not physical or statistical qualification.

PID/start-time/boot/process-group records support restart checks. A live parent signals only its still-owned group. Recorded single-process fixture recovery uses pidfds to prevent PID-reuse signaling and waits for exit; failed cancellation leaves the reservation occupied. Arbitrary native process trees, MPI, GPU and adversarial filesystem/cgroup isolation are Unsupported, not qualified by these tests.
